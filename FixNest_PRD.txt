1. Overview & Problem Statement
Gated communities and townships route every maintenance issue — electrical, plumbing, cleaning — through a manual, opaque process: a resident calls or messages the secretary or management office, who then verbally coordinates with an on-call technician. There is no tracking, no verification of work quality, no SLA, and no data trail.
This causes:
Delayed resolution with no visibility for the resident
No proof that reported issues were actually fixed
No accountability or rating system for vendors
No structured data for management to spot recurring problems
Local, capable electricians/plumbers in smaller cities remain undiscovered and underemployed, while big cities over-rely on expensive aggregators
FixNest is a middleware SaaS platform connecting residents of gated communities to verified electricians, plumbers, and cleaning staff through a gated, community-authenticated environment — with AI-assisted ticket triage, geo-tag-verified proof of work, and a two-tier vendor strategy that adapts to city size.
Core promise: raise a ticket → AI validates and prioritizes it → community secretary approves/routes it → a vendor (partner API or local onboarded professional) fixes it → geo-tag-matched proof photo closes the loop → resident rates the job.
2. Goals & Success Metrics
2.1 Product Goals
Replace the manual complaint/coordination process with a tracked, structured digital pipeline.
Give residents visibility into ticket status from raise to resolution.
Give facility management structured data on recurring issues and vendor performance.
Create a two-sided marketplace that works for both tier-1 (aggregator-partnered) and tier-2/3 (own vendor network) cities.
Prevent fraudulent "job done" closures via geo-tag verification.

3. Users & Personas
Resident
Lives in the gated community. Raises tickets for maintenance issues with photo/video, auto-captured geo-tag, and unit number. Tracks ticket status and confirms/rates job completion.
Secretary / Facility Admin
Manages the community's ticket queue. Reviews AI-tagged tickets, approves or manually routes high-severity/ambiguous ones, oversees vendor assignment, and handles escalations and disputes.
Vendor (Electrician / Plumber / Cleaner)
Either an aggregator-partner technician (Tier-1 cities, routed via API) or an independently onboarded local professional (Tier-2/3 cities, part of FixNest's own network). Receives job assignment, completes work, uploads geo-tagged proof photo.
Platform / Housing Management Company (B2B)
Subscribes to the analytics layer to see aggregate data — recurring issues by building/block, fastest and best-rated vendors — across one or more managed communities.
4. Scope
4.1 In Scope (Hackathon MVP)
Resident ticket creation with photo/video upload, category selection, auto geo-tag, unit number.
AI triage layer: image classification, severity/urgency scoring, duplicate detection, spam/fraud filter.
Secretary/Admin dashboard with AI-tagged ticket queue and approve/route actions.
Auto-approval path for low-severity, high-AI-confidence tickets.
Vendor assignment logic: API-partner routing (Tier-1 simulation) vs. local network routing (Tier-2/3 simulation).
Vendor job flow: accept job, mark complete, upload geo-tagged "after" photo.
Geo-tag mismatch check between intake and completion coordinates.
Resident confirm + rate step (single combined action).
Low-rating auto-reopen and escalation to secretary.
Basic B2B analytics view (aggregate ticket/vendor stats).
4.2 Out of Scope (Post-Hackathon / Future Phases)
Real payment settlement/processing integration.
Production-grade vendor background-check/ID verification pipeline (stub/mock for demo).
Real aggregator API integrations (Urban Company, Housejoy, etc.) — simulate with a mock API partner.
Push notification infrastructure at scale (use simple webhook/toast simulation for demo).
Multi-language support.
Native mobile apps (web-responsive is sufficient for MVP).
5. End-to-End System Flow
This is the authoritative flow the system must implement, derived from the architecture diagram.
Resident raises a ticket: selects category, attaches photo/video, system auto-captures geo-tag, resident confirms unit number.
AI Triage Layer processes the ticket:
Image classification — does the photo match the claimed issue category?
Severity/urgency scoring — e.g. exposed wire = critical, dripping tap = routine
Duplicate detection — same issue already reported in the same block/time window?
Spam/fraud filter — flags repeat frivolous tickets from the same user
Ticket reaches the Secretary/Facility Admin Dashboard with the AI severity tag and suggested vendor tier.
Low-severity, high-AI-confidence tickets can auto-approve.
High-severity or ambiguous tickets require manual secretary approval.
Vendor Assignment (tier-based):
Tier-1 cities → routed via API Partnership with existing aggregators.
Tier-2/3 cities → routed to the FixNest Local Network of onboarded independent vendors.
Vendor completes the job and uploads a geo-tagged "after" photo.
System checks the "after" photo geo-tag against the "before" geo-tag within a threshold (e.g. 20m).
Match → proceeds to closure.
Mismatch → auto-flagged for secretary review as a fraud/location-spoofing signal.
Resident is notified, confirms resolution, and rates the job in a single combined step.
A low rating auto-reopens the ticket (it is not silently closed) and escalates it to the secretary.
Completed job data feeds the B2B Analytics Layer for housing management reporting.

9. AI Component Specification
Scoped to be concretely demoable rather than a claimed black box:
Image Classification
Lightweight model (fine-tuned CLIP or small CNN) trained/tested on a small labeled sample set covering classes such as "electrical fault," "leak/water damage," and "unclean area." Even moderate accuracy is acceptable — a working live demo outperforms a claimed capability.
Severity Scoring
Rule-based or simple weighted model combining category, keyword signals from the description, and image-classification confidence. Does not require deep learning to be credible.
Duplicate Detection
Basic similarity check: same block + same category + overlapping time window.
Geo-Tag Mismatch Check
Simple distance calculation (e.g. Haversine formula) between before/after coordinates — cheap to build and highly effective to demo live.
10. Trust, Safety & Accountability
Vendor verification: ID proof + background-check tier required before onboarding (critical for liability, since residents let vendors into their homes).
Dispute resolution flow: disputed or reopened jobs follow a defined escalation path — secretary → admin → refund/re-assignment — rather than an undefined dead end.
Payment settlement clarity: resident pays via the platform, which settles with the vendor minus commission (alternative: vendor collects directly and platform invoices commission separately). This must be explicit since it underpins the commission-based revenue model.
11. Non-Functional Requirements
Category
Requirement
Performance
AI triage result should return within a few seconds of ticket submission for a responsive demo experience.
Reliability
Geo-tag and photo uploads must be stored durably before triage runs, so a triage failure never loses the original submission.
Usability
Resident, Secretary, and Vendor views must each be usable without training — clear status labels at every step.
Security
Resident and vendor data (photos, geo-tags, contact info) scoped to the resident's own community; admin views scoped to their managed community/communities.
Auditability
Every status transition (approve, assign, complete, geo-check, rate, reopen) is timestamped and retained for the dispute/escalation flow.
